### 3a. 四個阻斷性錯誤（呼叫即炸）

| 位置 | 問題 |
|---|---|
| `:41` | 方法簽名缺 `self`；`:70` 又只傳一個引數 → `TypeError: missing 2 required positional arguments` |

目標形狀（`AsyncSessionLocal` 用法比照 `branches/metadata.py:21,136`）：

```python
class SQLSummaryIndexClient:
    async def fetch_document_summaries(
        self, tenant_id: str, user_id: str, knowledge_base_id: str
    ) -> list[Chunk]:
        stmt = select(
            Document.id, Document.filename, Document.summary
        ).where(
            Document.tenant_id == uuid.UUID(tenant_id),
            Document.user_id == uuid.UUID(user_id),
            Document.knowledge_base_id == uuid.UUID(knowledge_base_id),
            Document.status == IngestionStatus.INDEXED,
            Document.summary.is_not(None),
            Document.deleted_at.is_(None),
        )
        async with AsyncSessionLocal() as db:
            rows = (await db.execute(stmt)).all()
        return [
            Chunk(chunk_id=str(row.id), content=row.summary, source=row.filename)
            for row in rows
        ]
```

三點理由：只 select 需要的欄位（原本 `select(Document)` 會把 `raw_text` 整篇撈回來）；補上 `summary IS NOT NULL` / `deleted_at IS NULL`（`docs/document-summary-storage.md:103` 定的條件，缺前者會讓空字串進 map-reduce 而 `if not summaries` 擋不住）；`str` → `UUID` 接縫顯式寫出。`:48` 的 `all_docs_result = []` 是死碼，刪掉。

### 3c. `_map_reduce` 的穩健性（`:85-99`）

- **`asyncio.gather`（`:96`）沒有併發上限、沒有 `return_exceptions`** — 500 份文件 = 瞬間 63 個並行請求會 429，且任一 batch 失敗就整次丟掉。加模組層級 `asyncio.Semaphore` 包住 `complete`。
- **`_batch_size <= 1` 無限迴圈** — `__init__`（`:59-65`）沒檢查；batch 數等於輸入數時 `len(current)` 永不遞減。加 `if batch_size < 2: raise ValueError(...)`。
- **`texts=[]` → `current[0]` IndexError**（`:99`），保護只在呼叫端。`_map_reduce` 開頭補 `if not texts: return ""`。
- （次要）reduce 階段沿用 `_build_map_prompt`，但第二輪以後的輸入已是中間摘要。可拆 `_build_reduce_prompt`，用 `first_pass` 判斷。
